export function updateHabitMemory(deviceId, category, amount) {

const key = habit_${category}


const existing = getUserMemory(deviceId)


const habit = existing[key] || { count: 0, total: 0, avg: 0 }


habit.count += 1


habit.total += amount


habit.avg = Math.round(habit.total / habit.count * 100) / 100


updateMemory(deviceId, key, habit)


}

3.2 关键技术决策

序号决策理由
1双模式 NLU 引擎Claude API 驱动智能理解 + 本地规则引擎降级。确保无 API Key 时仍可演示，降低演示风险
2ESM 模块系统全项目使用 ES Module（"type": "module"），与 Vue 3 + Vite 生态一致，避免 CJS/ESM 混用问题
3dotenv 延迟加载将 API Key 检查从模块顶层常量改为函数内运行时判断，解决 ESM import hoisting 导致的环境变量未加载问题
4SQLite + WAL 模式使用 WAL 模式提升并发读写性能，单文件部署简单，适合个人应用
5设备ID替代注册登录localStorage UUID 识别用户，降低使用门槛，符合"打开即用"的设计理念

4.2 协同案例

#### 案例：NLU引擎双模式架构的迭代过程

背景：选题报告规划使用 Claude API 处理自然语言记账。但实际开发中需要考虑演示场景（评审老师可能没有 API Key）。

协作过程：

1. 初始方案：Agent 最初设计了纯 Claude API 方案，在 nlu.js 中直接调用 Anthropic SDK。

2. 发现问题：我指出需要考虑无 API Key 的演示场景。Agent 提出增加"本地规则引擎"作为降级方案——当检测不到有效 API Key 时，使用正则匹配提取金额、关键词推断类别。

3. 验证迭代：Agent 实现后，我测试发现"今天午餐花了25元"无法正确解析，Agent 通过调试发现是 curl 在 Windows 下传输中文的编码问题，实际浏览器请求正常。确认后 Agent 使用 Node.js fetch 重新验证通过。

4. 持续优化：上线后发现 ESM 的 import hoisting 导致 dotenv 在模块加载后才执行，API Key 始终为空。Agent 分析后提出：将模块顶层常量改为函数内运行时判断。修改后 API Key 正确加载，Claude 模式正常工作。

人-Agent分工：

  • 我：提出需求边界条件（需支持无API Key演示）、测试发现问题、确认修复方案
  • Agent：设计降级架构、实现正则匹配规则、排查编码问题、修复ESM加载时序Bug

#### 案例：项目规划与分步实施

协作过程：

1. Agent 先读取选题报告，自动进入 Plan Mode 设计完整架构方案

2. 我审核方案后批准，Agent 按照10步计划逐步实施

4.3 协同经验

1. 分步验证比一次性实现更重要：Agent 擅长快速生成大量代码，但如果一次性生成全部再测试，排查问题非常困难。本次开发中每完成一个后端路由就立即测试，发现问题立刻修复，效率更高。

2. 精确指令 > 模糊指令：一开始我说"实现一个财务记账助手"，Agent 先进入 Plan Mode 设计详细方案等我确认。如果直接跳过规划开始写代码，后期返工成本会很高。明确的架构方案和步骤计划是关键。

3. 人做决策，Agent做执行：Agent 能快速写出代码，但不知道项目的约束条件（如"演示时可能没有API Key"）。我的价值是提供这些边界条件、验证实际效果、判断方案合理性。Agent 负责实现细节，我负责把握方向。

五、问题与调整

5.1 遇到的问题

序号问题原因解决过程
1ESM import hoisting 导致环境变量未加载import 语句在模块顶层代码执行前全部解析，dotenv.config() 在 process.env 被使用后才执行将 API Key 检查从模块顶层常量（const HAS_API_KEY）改为函数内运行时判断（getAnthropicClient()），确保 dotenv 先加载
2Windows bash curl 中文编码问题curl 在 Windows bash 环境下传输 UTF-8 中文时编码转换出错，服务端收到乱码改用 Node.js 内置 fetch() 进行测试（浏览器原生 UTF-8 编码不受影响）。前端使用浏览器 fetch 无此问题
3Claude API 返回 JSON 解析失败Claude 偶尔在 JSON 前后添加额外文字说明使用正则 /[\s\S]*\}/ 提取 JSON 块，外层 try-catch 兜底返回友好提示
4预算数据未包含实际支出预算GET接口最初只返回预算金额本身，前端需要自行查询支出修改 GET /api/goals/budgets 接口，在服务端 JOIN records 表计算实际支出和百分比后统一返回

前端Vue 3 + Vite + Pinia + Vue Router + ECharts
后端Node.js + Express + better-sqlite3
AIClaude API (Anthropic SDK)
数据SQLite (WAL模式)

C. 运行方式

1. 配置API Key (在 server/.env 中填入 ANTHROPIC_API_KEY)


2. 安装依赖


npm run install:all


3. 启动（前后端同时）


npm run dev
