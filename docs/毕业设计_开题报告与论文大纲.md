## 一、开题报告

### 1.1 选题背景与意义

#### 1.1.1 选题背景

随着我国数字经济的快速发展，个人财务管理正从传统的手工记账向智能化、自动化方向演进。然而，现有财务管理软件普遍存在以下问题：

1. **交互门槛高**：传统记账软件要求用户手动选择分类、填写金额、指定日期，操作繁琐，用户留存率低；
2. **缺乏智能分析**：多数产品仅提供简单的收入支出记录，无法基于用户消费数据提供个性化的财务建议；
3. **安全与隐私不足**：AI 驱动的财务系统面临 SQL 注入、越权访问、敏感操作无确认等安全风险；
4. **架构扩展性差**：单体架构难以支持多租户、灰度发布、功能开关等企业级需求。

与此同时，2024-2025 年大语言模型（LLM）和 AI Agent 技术取得了突破性进展。LangGraph 作为 LangChain 生态中的状态图编排框架，为构建复杂的多智能体协作系统提供了坚实的基础。DeepSeek 等国产大模型在中文理解和推理能力上已达到国际一流水平，使得基于 LLM 的智能财务助手成为可能。

#### 1.1.2 选题意义

**理论意义**：
- 探索了 LangGraph StateGraph 在财务管理领域的应用模式，提出了"12 节点 + 条件路由"的 Agent 编排方案；
- 设计了四层记忆系统（会话元数据 / 长期记忆 / 近期摘要 / 滑动窗口），为 LLM Agent 的上下文管理提供了可参考的架构；
- 提出了"SQL AST 语法守卫 + 工具白名单 + 敏感操作确认"的三级安全防线，为 LLM Agent 的安全可控提供了工程实践。

**实践意义**：
- 开发了一套完整的智能财务管理平台（已上线 https://lisheng666.xyz），覆盖智能记账、账单分析、财务顾问、多账本管理等核心场景；
- 实现了企业级架构特性：多租户、RBAC 权限控制、审计日志、CSV 数据导出、可观测性、CI/CD 自动化部署；
- 项目 610 个测试用例全部通过，22 个 Agent 评估用例覆盖 7 个维度，具备良好的工程质量。

### 1.2 国内外研究现状

#### 1.2.1 AI Agent 研究现状

2023 年以来，以 AutoGPT、MetaGPT、CrewAI 为代表的多智能体框架引发了 AI Agent 研究热潮。LangGraph 作为 LangChain 推出的状态图编排框架，通过显式的状态管理和条件路由机制，解决了传统 AgentExecutor 黑盒循环难以控制和调试的问题。

#### 1.2.2 智能财务管理应用现状

国外产品如 Mint（已关闭）、YNAB、Monarch Money 在预算管理和财务规划方面较为成熟，但缺乏中文自然语言交互能力。国内产品如随手记、挖财、鲨鱼记账等拥有较大用户基数，但智能化程度有限，多依赖规则引擎而非 LLM 进行意图理解。

#### 1.2.3 现有研究不足

- 缺乏将 LangGraph 多智能体架构系统性地应用于财务管理领域的研究；
- LLM Agent 的安全性问题（SQL 注入、越权访问）在财务场景下尤为突出，但现有研究对此关注不足；
- 缺乏从本地开发到生产部署的完整工程实践。

### 1.3 研究内容

本课题围绕"如何构建一个安全、智能、可扩展的 AI 财务管理平台"这一核心问题，开展以下研究：

1. **LangGraph 多智能体编排**：设计并实现基于 StateGraph 的 12 节点 Agent 工作流，包括意图识别、上下文组装、模型推理、工具调用、安全确认、记忆更新等节点，以及 3-Agent 主从协同架构（Master / Retrieval / Calculator）。

2. **四层记忆系统**：设计会话元数据（L1）、用户长期记忆（L2）、近期摘要（L3）、滑动窗口（L4）四层记忆架构，实现 Agent 的跨会话、跨轮次的上下文感知能力。

3. **三级安全防线**：设计 SQL AST 语法守卫（白名单 + LIMIT 强制 + 自动作用域注入）、工具可信字段注入、敏感操作 LangGraph interrupt 人机确认三层防护机制。

4. **企业级架构特性**：实现多租户数据隔离、RBAC 四级权限控制、审计日志追踪、CSV 数据导出、可观测性指标采集、CI/CD 自动化部署流水线。

5. **系统实现与评估**：完成前后端全栈开发、Docker Compose 容器化部署、610 个单元测试和 22 个 Agent 评估用例，并通过生产环境实际运行验证系统可用性。

### 1.4 研究目标

1. 构建一个支持自然语言交互的智能财务管理系统，核心功能包括智能记账、账单查询、财务分析、财务顾问、多账本管理；
2. 实现 LangGraph 多智能体编排架构，支持 12 节点工作流和 3-Agent 主从协同；
3. 建立完善的记忆系统和安全防线，确保 Agent 行为的可控性和数据安全性；
4. 完成企业级架构设计，支持多租户、RBAC、审计、CI/CD 等特性；
5. 系统通过 610 个测试用例验证，并在生产环境稳定运行。

### 1.6 创新点

1. **LangGraph 多智能体编排在财务领域的首次系统应用**：设计了 12 节点 StateGraph + 3-Agent 主从协同的双层架构，支持意图识别、条件路由、安全确认、记忆更新等完整的 Agent 工作流。

2. **四层记忆系统**：从会话元数据到长期用户画像的四层记忆架构，实现了 Agent 的上下文感知和个性化服务能力，且每层独立降级，不互相影响。

3. **三级安全防线**：创新性地将 SQL AST 语法守卫引入 LLM Agent 工具调用链路，结合可信字段注入和 LangGraph interrupt 机制，构建了纵深防御的安全体系。

4. **Feature Flag 灰度架构**：通过环境变量控制所有可选能力，结合用户 ID 哈希分桶实现 0-100% 的精细化灰度发布，支持秒级回滚。

### 3.2 答辩常见问题预演

| 问题 | 准备回答 |
|------|----------|
| 为什么选 LangGraph 而不是直接用 LangChain？ | LangGraph 提供显式状态管理 + 条件路由 + interrupt，比 AgentExecutor 黑盒循环更适合需要安全控制的财务场景 |
| 你的系统和 ChatGPT 记账有什么区别？ | ChatGPT 是通用对话，本系统有领域专用工具、SQL 安全守卫、多租户数据隔离、审计日志等企业级特性 |
| 四层记忆的必要性？ | 每层记忆的作用域和生命周期不同：L1 会话级偏好、L2 跨会话用户画像、L3 单会话摘要、L4 短窗口上下文。分层可独立降级，防止单点故障影响全局 |
| SQL Guard 能防住所有注入吗？ | AST 级别的语法校验 + 表白名单 + 函数白名单 + LIMIT 强制 + 作用域注入五重防护，理论上可以阻绝大部分注入，但不能宣称 100% |
| 系统有什么不足？ | OCR 准确率待提升、移动端体验待优化、财务建议个性化程度有限 |
