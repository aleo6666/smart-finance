# 第 1 章 绪论

## 1.1 研究背景与意义

### 1.1.1 个人财务管理的数字化转型

随着我国数字经济的蓬勃发展，居民收入水平和消费能力持续提升，个人财务管理的重要性日益凸显。根据中国人民银行发布的《2025 年支付体系运行总体情况》，2025 年我国移动支付业务量达到 1.85 万亿笔，同比增长 12.3%，人均持有银行卡 6.8 张，个人金融活动的复杂度显著增加[1]。在这一背景下，个人财务管理工具从传统的手工记账本、Excel 电子表格，逐步演进为移动 App 和云端服务，用户对于记账便捷性、分析智能化和数据安全性的需求不断提升。

然而，当前市场上的个人财务管理产品仍存在明显的局限性。首先，交互门槛较高——用户需要手动选择分类、输入金额、指定日期，操作流程繁琐，导致大量用户在初次使用后放弃。根据 App Annie 的统计数据，财务管理类 App 的 30 日留存率平均仅为 12%，远低于社交和娱乐类应用[2]。其次，分析能力不足——多数产品仅提供简单的收支汇总和图表展示，无法基于消费数据提供深度的财务健康诊断和个性化的改进建议。再次，安全性参差不齐——部分产品在数据存储和传输环节缺乏足够的安全防护措施，用户财务隐私面临泄露风险。

### 1.1.2 大语言模型与 AI Agent 技术的突破

2022 年末 OpenAI 发布 ChatGPT 以来，大语言模型（Large Language Model，LLM）技术经历了爆发式发展。GPT-4、Claude、Gemini 等国外模型以及 DeepSeek、通义千问、文心一言等国产模型在自然语言理解、逻辑推理、代码生成等任务上取得了令人瞩目的成绩[3][4]。特别是 DeepSeek V3/V4 系列模型，在中文理解和推理能力上已达到国际一流水平，且推理成本大幅降低，为 LLM 技术在实际应用中的广泛落地创造了条件[5]。

与此同时，AI Agent 作为一种将 LLM 与实际工具调用相结合的智能体架构，正在从实验室走向工程实践。AI Agent 不再局限于文本生成，而是能够感知环境、制定计划、调用工具、执行操作，形成完整的"感知-决策-执行"闭环[6]。2024 年以来，以 LangGraph、AutoGPT、MetaGPT、CrewAI 为代表的 Agent 框架不断涌现，其中 LangGraph 以其显式的状态图编排、条件路由和人机交互（interrupt）机制，成为构建复杂多智能体系统的首选框架[7]。

### 1.1.3 选题意义

本课题具有以下理论意义和实践意义：

**理论意义**：

第一，探索了 LangGraph StateGraph 在智能财务管理领域的应用模式。本课题设计了包含 12 个节点的 Agent 工作流，涵盖记忆加载、意图识别、上下文组装、模型推理、工具调用、安全确认和记忆更新等完整链路，为 LLM Agent 在垂直领域的应用提供了可参考的架构设计范式。

第二，提出了四层记忆系统的设计模型。本课题将 Agent 的记忆分为会话元数据（L1）、用户长期记忆（L2）、近期摘要（L3）和滑动窗口（L4）四个层级，每层独立管理、独立降级，为 LLM Agent 的上下文感知能力提供了系统性的记忆架构方案。

第三，构建了三级安全防线的纵深防御体系。通过 SQL AST 语法守卫、工具可信字段注入和敏感操作 LangGraph interrupt 确认三道防线，本课题为 LLM Agent 的安全可控性提供了工程实践方案，填补了 Agent 安全领域的研究空白。

**实践意义**：

第一，本课题开发了一套完整的智能财务管理平台，已部署于阿里云 ECS 并可通过 https://lisheng666.xyz 访问。平台覆盖智能记账、账单查询、财务分析、财务顾问、多账本管理等核心场景，具备实际使用价值。

第二，本课题实现了企业级架构特性，包括多租户数据隔离、RBAC 四级权限控制、审计日志追踪、CSV 数据导出、可观测性指标采集和 CI/CD 自动化部署，为同类系统的工程化开发提供了完整案例。

第三，项目通过了 610 个单元测试和 22 个 Agent 评估用例的验证，测试覆盖率达到 100%，展示了良好的软件工程质量，可作为软件工程专业本科毕业设计的实践范例。

## 1.2 国内外研究现状

### 1.2.1 AI Agent 框架研究现状

AI Agent 的研究可追溯至强化学习领域的智能体概念，但基于 LLM 的 Agent 范式在 2023 年后才真正兴起。2023 年 3 月，AutoGPT 的发布引发了全球范围内的 AI Agent 热潮，它首次展示了 LLM 自主规划、工具调用和迭代执行的能力[8]。同年，MetaGPT 提出了基于标准化操作规程（SOP）的多智能体协作框架，模拟软件公司的角色分工（产品经理、架构师、工程师、测试员）来协同完成软件开发任务[9]；CrewAI 提供了角色扮演式的多 Agent 编排方案，支持定义 Agent 的角色、目标和工具集[10]。

然而，上述框架在实际应用中暴露出了共性问题：AgentExecutor 的"黑盒循环"机制导致 Agent 行为难以预测和调试；工具调用缺乏有效的安全控制和参数校验；多轮对话中的状态管理依赖隐式的消息历史，缺乏显式的状态追踪。

针对这些问题，LangChain 团队于 2024 年推出了 LangGraph 框架。LangGraph 基于有向图模型，将 Agent 的工作流抽象为状态图（StateGraph）中的节点和边，支持条件路由、循环执行和人机交互中断（interrupt）等高级特性[7]。LangGraph 的显式状态管理使得 Agent 的每一步决策都可追踪、可审计，极大地提升了 Agent 系统的可控性和可观测性。2025 年以来，LangGraph 已被 OpenAI、Anthropic、Elastic 等企业广泛采用，成为构建生产级 Agent 系统的主流选择。

### 1.2.2 智能财务管理应用现状

在海外市场，个人财务管理（Personal Finance Management，PFM）应用经历了数十年的发展。Intuit 公司于 2006 年推出的 Mint 曾是美国最受欢迎的免费财务管理工具，提供自动银行同步、预算管理和账单提醒等功能，用户数一度超过 2000 万，但于 2024 年正式关闭[11]。You Need A Budget（YNAB）采用"零基预算"方法论，强调每一分钱都有用途，在预算管理领域具有较强影响力[12]。Monarch Money 作为 Mint 的后继者之一，支持多账户聚合和协作理财，代表了 PFM 产品向家庭财务协作方向演进的趋势[13]。

在国内市场，随手记、挖财、鲨鱼记账等产品拥有较大的用户基数。随手记自 2010 年上线以来累计用户超过 3 亿，是国内用户量最大的记账工具之一[14]。然而，这些产品在智能化方面存在明显不足：记账分类依赖用户手动选择，分析报告停留在统计图表层面，缺乏基于自然语言交互的智能查询和个性化财务建议能力。

需要特别指出的是，目前将 LLM 与 AI Agent 技术系统性地应用于财务管理领域的研究仍十分有限。现有工作多聚焦于大模型在金融文本分析、风险预测等机构金融场景的应用[15]，面向个人用户的智能财务管理 Agent 研究尚处于起步阶段。

### 1.2.3 大语言模型安全研究现状

LLM Agent 的安全性是一个新兴且紧迫的研究方向。Ouyang 等人（2022）在 InstructGPT 中首次系统性地探讨了 LLM 的对齐（Alignment）问题[16]。Wei 等人（2023）提出了"越狱攻击"（Jailbreaking）的概念，展示了 LLM 在对抗性提示下可能绕过安全限制[17]。

在 LLM Agent 的场景下，安全问题更为复杂。Agent 不仅输出文本，还要调用外部工具、执行数据库操作、访问用户数据，每一个环节都可能引入新的攻击面。Greshake 等人（2023）提出了"间接提示注入"（Indirect Prompt Injection）攻击模型，攻击者可以通过在 Agent 检索的外部文档中嵌入恶意指令来操控 Agent 的行为[18]。

在财务场景下，安全问题尤为关键。传统 Web 应用中的 SQL 注入攻击在 Agent 系统中可能以新的形式出现——LLM 生成的 SQL 查询可能包含恶意构造的子查询、UNION 注入或无限制的全表扫描。然而，现有的 LLM 安全研究主要聚焦于内容安全和价值对齐，对于 Agent 工具调用链路中的结构化安全防护（尤其是 SQL 安全）关注不足，这正是本课题要重点解决的问题之一。

### 1.2.4 现有研究的不足与本文定位

综合以上分析，现有研究存在以下不足：

第一，**Agent 架构在垂直领域的应用研究不足**。现有 Agent 研究多停留在通用框架层面，缺乏将 LangGraph 多智能体架构系统性地应用于财务管理等垂直领域的设计实践和工程验证。

第二，**Agent 上下文记忆缺乏系统性方案**。多数 Agent 系统仅使用简单的滑动窗口机制，未区分不同生命周期和作用域的记忆层级，导致长期用户画像缺失、跨会话上下文断裂。

第三，**Agent 工具调用的安全防护研究薄弱**。SQL 注入、越权访问等传统 Web 安全问题在 Agent 场景下以新形式出现，但缺乏针对性的纵深防御方案。

第四，**缺乏从开发到生产的全链路工程实践**。学术界的研究多停留在原型验证阶段，未覆盖 Feature Flag 灰度发布、可观测性、CI/CD 部署等企业级工程实践。

本课题针对上述不足，以"基于 LangGraph 多智能体的智能财务管理系统"为题，从 Agent 架构设计、记忆系统、安全防线和工程化部署四个维度展开研究，并通过 610 个测试用例和 22 个 Agent 评估用例进行系统验证，最终交付一个可生产部署的完整系统。

## 1.3 研究内容

本课题围绕"如何构建一个安全、智能、可扩展的 AI 财务管理平台"这一核心问题，开展以下五个方面的研究：

### 1.3.1 LangGraph 多智能体编排

研究基于 LangGraph StateGraph 的 Agent 工作流设计方法。具体包括：设计 12 节点的 Agent 工作流（loadMemory → normalize → compose → model → validate/risk_check/confirm → tool_node → postTurnMemory → END），实现条件路由策略（读操作/写操作/无工具三分支），以及 3-Agent 主从协同架构（Master Agent 负责任务分解和结果汇总，Retrieval Agent 负责数据检索，Calculator Agent 负责指标计算）。此外，还将研究基于 Zod Schema 的 AgentState 类型约束设计，确保状态数据的类型安全和结构一致。

### 1.3.2 四层记忆系统

研究面向 LLM Agent 的分层记忆架构。具体包括：L1 会话元数据（设备类型、时区、交互偏好等会话级信息）、L2 用户长期记忆（消费习惯、理财目标、重要日期等跨会话持久化信息）、L3 近期摘要（当前话题、未完成任务、分析结论等自动生成的动态摘要）、L4 滑动窗口（最近 N 轮对话上下文）。重点研究四层记忆的并行加载机制、独立降级策略和自动更新流程，以及在 MySQL、Redis 和 LangGraph Checkpointer 中的存储方案。

### 1.3.3 三级安全防线

研究 LLM Agent 工具调用链路的安全防护方案。具体包括：第一道防线——SQL AST 语法守卫，基于 node-sql-parser 对 LLM 生成的 SQL 进行文本过滤（拦截分号、注释、危险函数）、AST 结构校验（只允许 SELECT 语句，禁止子查询/UNION/CTE）、表白名单与函数白名单、自动作用域注入（WHERE user_id = ?）和 LIMIT 强制限制（最大 200 行）五重防护；第二道防线——工具可信字段注入，确保 userId、sessionId 等身份字段来自服务端 Runtime Context 而非模型输出；第三道防线——敏感操作确认，利用 LangGraph 的 interrupt 机制，对写操作（记账、预算修改、记忆写入）进行人机交互确认。

### 1.3.4 企业级架构特性

研究面向多租户场景的企业级架构设计。具体包括：基于账本（Ledger）和团队（Team）的多租户数据隔离模型；基于 admin/manager/member/viewer 四级的 RBAC 权限控制；基于 auditLog 中间件的操作审计日志记录；支持 BOM 编码兼容 Microsoft Excel 的 CSV 数据导出；基于 observability 中间件的系统指标采集（请求量、延迟、错误率、Agent 工具调用次数）；基于 GitHub Actions 的 CI/CD 自动化测试与部署流水线。

### 1.3.5 系统实现与评估

完成智能财务管理平台的全栈开发与评估。前端采用 Vue 3 + Vite + Pinia + ECharts 技术栈，实现智能对话、数据可视化和账本管理等界面；后端采用 Node.js + Express + Knex 技术栈，实现 RESTful API 和 Agent 服务；数据库采用 MySQL 8 + Redis 7 + Qdrant 组合；部署采用 Docker Compose 七服务编排。通过 610 个单元测试和 22 个 Agent 评估用例（覆盖记账、查询、分析、预算、安全、记忆、路由 7 个维度）进行系统验证，并在阿里云 ECS 生产环境实际运行。

## 1.4 研究目标

本课题的具体研究目标如下：

1. **智能交互目标**：构建支持自然语言交互的智能财务管理系统，用户可通过自然语言完成记账、查询、分析和咨询，无需手动选择分类和填写表单。系统需支持中英文双语交互，记账准确率不低于 90%。

2. **Agent 架构目标**：设计并实现 LangGraph 多智能体编排架构，包含 12 节点 StateGraph 工作流和 3-Agent 主从协同机制。Agent 系统需支持条件路由、人机交互确认、工具调用计数和递归限制等控制机制。

3. **记忆系统目标**：建立四层记忆系统，实现 Agent 的跨会话和跨轮次上下文感知能力。四层记忆需支持独立加载和独立降级，任一层的故障不影响其他层的正常工作。

4. **安全防护目标**：建立三级安全防线，SQL 注入防护需达到 AST 级别，敏感操作需经过人机确认，用户数据需实现严格的租户隔离。Feature-Off 兼容测试需达到 100% 通过率。

5. **工程质量目标**：系统需通过 610 个单元测试（100% 通过率）和 22 个 Agent 评估用例验证，实现 CI/CD 自动化部署，在生产环境稳定运行。

## 1.6 论文组织结构

本论文共分为七章，各章节的内容安排如下：

**第 1 章 绪论**。阐述课题的研究背景与意义，综述 AI Agent 框架、智能财务管理应用和 LLM 安全领域的国内外研究现状，明确研究内容、研究目标和技术路线，并介绍论文的组织结构。

**第 2 章 相关技术综述**。系统介绍本课题涉及的关键技术，包括大语言模型与 AI Agent 原理、LangGraph 状态图编排框架、Vue 3 与 Node.js 技术栈、MySQL/Redis/Qdrant 数据库选型分析，以及 Docker Compose 容器化部署方案。

**第 3 章 系统需求分析**。从业务需求、功能性需求和非功能性需求三个维度进行系统需求分析，明确智能记账、账单查询、财务分析、财务顾问等核心功能需求，以及性能、安全、可用性、可维护性和可扩展性的非功能需求。

**第 4 章 系统设计**。详细阐述系统的总体架构设计、LangGraph 多智能体编排设计、四层记忆系统设计、三级安全防线设计、灰度架构设计、数据库设计、前端架构设计和 RESTful API 设计。

**第 5 章 系统实现**。介绍系统的核心实现细节，包括 LangGraph Agent 核心实现、工具系统实现、记忆系统实现、安全防护实现、企业级特性实现、前端界面实现和容器化部署实现。
