## 📌 题目方案

### 方案 A（推荐）：Agent 架构主线

> **基于 LangGraph 多智能体的智能财务管理系统设计与实现**

**Design and Implementation of an Intelligent Financial Management System Based on LangGraph Multi-Agent Architecture**

**选这个的理由**：LangGraph 是 2024-2025 最火的 Agent 框架，你的项目真实用了它的 StateGraph + interrupt + Checkpointer，不是包装 API。答辩时有技术深度可讲。

---

### 方案 B：安全 + Agent 双线

> **面向 LLM 多智能体的安全财务管理系统设计与实现**

**Design and Implementation of a Secure Financial Management System with LLM Multi-Agent**

**选这个的理由**：如果你的导师偏向信息安全方向，SQL AST 守卫 + 三级防线 + 敏感操作 interrupt 可以单独成章，差异化明显。

---

### 方案 C：工程化架构线

> **基于 AI Agent 的企业级 SaaS 财务管理平台设计与实现**

**Design and Implementation of an Enterprise SaaS Financial Management Platform with AI Agent**

**选这个的理由**：突出多租户、RBAC、审计、CI/CD、灰度发布等企业特性，适合想展示全栈工程能力的路线。

---

### 方案 D：记忆系统线

> **基于分层记忆机制的大模型财务智能体设计与实现**

**Design and Implementation of an LLM Financial Agent with Hierarchical Memory Mechanism**

**选这个的理由**：四层记忆是你项目独有的设计（很少有本科毕设做这个），差异化极大，但题目偏窄。

---

## 🎯 推荐：方案 A

理由：
1. **LangGraph 是核心**：你项目的灵魂是 StateGraph 编排，不是简单调 API
2. **题目覆盖面够**：A 方案是最"正"的题目，能覆盖全部内容
3. **导师好理解**：不会太偏安全，也不会太偏工程，正统 CS 课题

**关键词**：LangGraph；多智能体；财务管理；大语言模型；记忆系统；安全防线

```

4.2 LangGraph 多智能体编排设计      ⭐
    4.2.1 Agent 总体架构
        - 12 节点 StateGraph（loadMemory → normalize → compose →
          model → validate/risk_check → tool_node → postTurnMemory）
        - 条件路由（只读/写操作/无工具三分支）
    4.2.2 节点职责详解
        - loadMemory：四层记忆并行加载
        - normalize：意图识别与请求标准化
        - compose：动态 System Prompt 组装
        - model：LLM 推理与工具选择
        - validate：工具参数 Zod 校验
        - risk_check：写操作安全风险评估
        - confirm：LangGraph interrupt 人机确认
        - tool_node：工具执行（8 个工具）
        - postTurnMemory：记忆更新与摘要生成
        - observe：可观测性指标采集
        - synthesize：财务分析结果合成
    4.2.3 AgentState Schema 设计（Zod 类型约束，14 个字段）
    4.2.4 3-Agent 主从协同架构（Master/Retrieval/Calculator）
    4.2.5 子图设计（domainAnalysis 财务分析子图）

4.3 工具系统设计                    ⭐
    4.3.1 工具分类（只读查询 / 计算分析 / 写入操作 / 管理操作）
    4.3.2 领域查询工具（query_transactions, calculate_finance_metrics）
    4.3.3 智能记账工具（record_transaction：自动分类 + 大额确认）
    4.3.4 财务顾问工具（advisorTool：健康评分 5 维度加权）
    4.3.5 知识库检索工具（knowledgeTool：Qdrant 语义搜索）
    4.3.6 管理 SQL 工具（adminSqlTool：受 SQL Guard 保护）
    4.3.7 OCR 识别工具（ocrTool：PaddleOCR 票据识别）

4.4 四层记忆系统设计                ⭐
    4.4.1 记忆分层架构总览
    4.4.2 L1 会话元数据（设备、时区、输入模式、回复风格）
    4.4.3 L2 用户长期记忆（消费习惯、理财目标、重要日期）
        - MySQL 持久化 + CRUD 接口
    4.4.4 L3 近期摘要（LLM 自动生成的结构化摘要）
        - 核心字段：currentTopics, unfinishedTasks, analysisConclusions
    4.4.5 L4 滑动窗口（Redis Checkpointer 持久化）
    4.4.6 记忆加载流程（Promise.allSettled 并行加载 + 独立降级）
    4.4.7 记忆更新流程（postTurnMemory 自动触发）

4.5 三级安全防线设计                ⭐
    4.5.1 纵深防御架构
    4.5.2 Line 1：SQL AST 语法守卫
        - 文本过滤（分号、注释、sleep/benchmark 拦截）
        - AST 校验（只允许 SELECT，禁止子查询/UNION/CTE）
        - 表白名单 + 函数白名单（19 个安全函数）
        - 自动作用域注入（WHERE user_id = ?）
        - LIMIT 强制（max 200 行）
    4.5.3 Line 2：工具可信字段注入
        (userId/sessionId 来自 Runtime Context，模型不可伪造)
    4.5.4 Line 3：敏感操作 interrupt 确认
        (记账/预算/记忆写操作需用户确认)
    4.5.5 JSON 容错修复（注释去除 + 引号转换 + 尾逗号修复）

4.6 灰度架构设计
    4.6.1 Feature Flag 机制（7 个环境变量开关）
    4.6.2 用户 ID SHA-256 哈希分桶

    4.6.4 LangGraph → Legacy 降级路径

4.7 数据库设计
    4.7.1 E-R 图
    4.7.2 核心表结构

        - finance_records, budgets, goals

    4.7.3 Redis 数据结构（会话缓存、频率限制、Checkpoint）
    4.7.4 Qdrant 集合设计（finance_records RAG 向量）

4.8 前端架构设计
```
