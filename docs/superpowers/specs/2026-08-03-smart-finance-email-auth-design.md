# Smart Finance 邮箱认证设计

**日期**：2026-08-03  
**状态**：已确认
**目标**：在不破坏现有手机号认证的前提下，增加“邮箱 + 密码”注册、登录和邮件验证码找回密码能力。

## 1. 背景与范围

个人项目暂时无法完成企业短信资质申请，因此需要一条可以真实部署、公开演示的认证路径。邮箱由个人邮箱的 SMTP 授权码发送 6 位验证码，注册必须先验证邮箱。

本期包含：

- 保留现有手机号注册、登录、找回密码和微信认证。
- 新增邮箱验证码注册、邮箱密码登录和邮箱验证码重置密码。
- 在登录页提供“手机号 / 邮箱”入口切换。
- 使用 Redis 保存验证码状态、发送频率和登录锁定状态。
- 使用个人邮箱 SMTP 授权码发送邮件，配置不绑定具体邮箱厂商。

本期不包含：

- 手机号账号与邮箱账号的自动合并或绑定。
- OAuth、Magic Link、Passkey 或社交登录。
- 修改已有手机号用户的数据和登录行为。
- 更换 JWT、密码哈希或会话体系。

## 2. 设计决策

采用独立的邮箱认证接口，而不是把手机号和邮箱合并为一个 `identifier` 接口。这样可以保持现有客户端契约不变，减少手机号回归风险，并让邮箱验证码的安全规则保持清晰。

邮件注册和找回密码都使用 6 位数字验证码。相比邮件链接，这种方式不依赖可公开访问的 HTTPS 回调地址，适合当前个人项目部署条件；相比“注册验证码 + 重置链接”的混合方式，它也更容易在一周内实现和测试。

邮箱账号本期不与手机号账号自动合并。相同自然人使用手机号和邮箱分别注册时会得到两个账号，这是明确接受的限制，避免因错误匹配造成财务数据串号。

## 3. 系统结构

### 3.1 后端组件

新增三个边界明确的组件：

1. `emailAuth` 路由：参数校验、HTTP 状态码、用户创建、登录、密码重置和 JWT 返回。
2. `emailVerificationService`：邮箱标准化、验证码生成和校验、Redis 状态、冷却与频率限制。
3. `emailService`：创建 SMTP transporter、渲染固定邮件模板并发送邮件。

现有手机号路由保持原接口。邮箱注册复用现有默认账本创建、游客记录迁移、`bcryptjs` 密码哈希和 JWT 签发逻辑；仅在必要时把默认账本和游客迁移函数提取为共享模块，不重构其他认证代码。

### 3.2 前端结构

登录卡片增加认证渠道切换：

- 手机号：保持现有登录、注册和找回密码表单及接口调用。
- 邮箱：提供登录、注册和找回密码三种状态。

邮箱注册和找回密码表单展示验证码输入框与 60 秒重发倒计时。切换渠道或表单状态时清空密码和验证码，浏览器刷新后也不持久化这些字段。

## 4. 数据模型与兼容策略

`users` 表新增：

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `email` | `VARCHAR(254)` | 可空、唯一 | 保存标准化后的邮箱 |
| `email_verified_at` | `DATETIME` | 可空 | 邮箱验证完成时间 |

现有用户的两个字段均为 `NULL`，不需要回填。MySQL 唯一索引允许多个 `NULL`，因此不会影响手机号或微信用户。

`schema.js` 的新建表定义包含这两个字段；`ensureSchema` 同时执行幂等的列与唯一索引检查，使已经部署的数据库也能安全升级。任何结构变更都只增加字段和索引，不删除或改写已有数据。邮箱注册时数据库唯一索引是并发重复注册的最终防线。

邮箱用户的 `username` 可以保持为空，`nickname` 使用脱敏邮箱；认证和数据归属始终以用户主键 `id` 为准。已认证的 `/me` 响应可以返回当前用户自己的邮箱和验证状态。

## 5. API 契约

所有新增接口挂载在 `/api/auth/email`，响应继续使用项目现有的 `{ success, data?, message?, error? }` 结构。

### 5.1 发送验证码

`POST /api/auth/email/send-code`

```json
{
  "email": "user@example.com",
  "purpose": "register"
}
```

`purpose` 只允许 `register` 或 `reset`。

- 注册场景：邮箱已注册时返回 `409`，未注册且发送成功时返回成功。
- 找回场景：无论邮箱是否存在、是否已验证或内部发送是否失败，外部都返回相同的受理提示，避免枚举账号。发送失败只进入脱敏日志和监控。
- 邮箱格式错误、冷却中或超过频率限制时返回稳定且不包含内部细节的错误。

### 5.2 邮箱注册

`POST /api/auth/email/register`

```json
{
  "email": "user@example.com",
  "code": "123456",
  "password": "******"
}
```

处理顺序：标准化并校验邮箱和密码、原子消费注册验证码、在事务内创建用户和默认账本、提交事务、迁移游客记录、签发 JWT。密码沿用现有至少 6 位和 bcrypt cost 10 的规则。成功响应与手机号注册一致，返回 `token` 和 `userId`。

只有验证码校验成功后才创建用户，并写入 `email_verified_at`。若唯一索引发现并发重复邮箱，返回 `409`；验证码已经消费时，调用方需要重新获取验证码。

### 5.3 邮箱登录

`POST /api/auth/email/login`

```json
{
  "email": "user@example.com",
  "password": "******"
}
```

登录只接受存在密码且 `email_verified_at` 非空的账号。邮箱不存在和密码错误统一返回“邮箱或密码错误”。连续失败 5 次后锁定 15 分钟；成功后清除锁定、更新 `last_login_at`、迁移游客记录并签发当前 30 天 JWT。

### 5.4 重置密码

`POST /api/auth/email/reset-password`

```json
{
  "email": "user@example.com",
  "code": "123456",
  "password": "new-password"
}
```

接口校验并原子消费 `reset` 验证码，只允许修改对应已验证邮箱账号。成功后更新 bcrypt 密码、删除该邮箱的登录失败锁定和剩余验证码状态，并提示用户重新登录。验证码错误、过期或尝试次数超限使用统一错误提示。

## 6. 验证码与频率控制

验证码使用 Node.js `crypto.randomInt` 生成并补齐为 6 位，有效期 5 分钟，发送后 60 秒内不能重发。每个验证码最多校验 5 次且只能成功使用一次。

Redis 不保存明文验证码或明文邮箱。邮箱标识和验证码摘要使用独立的 `EMAIL_OTP_SECRET` 做 HMAC，键按用途隔离，例如：

```text
email:otp:register:<email-hmac>
email:otp:reset:<email-hmac>
email:cooldown:<purpose>:<email-hmac>
email:attempts:<purpose>:<email-hmac>
email:rate:address:<email-hmac>
email:rate:ip:<ip-hmac>
login:lock:email:<email-hmac>
```

验证码校验与删除通过 Redis 原子操作完成，防止两个并发请求使用同一验证码。发送限制为同一邮箱每小时最多 5 次、同一 IP 每小时最多 20 次；现有 `/api/auth` 全局限流仍然生效。

Redis 不可用时，邮件验证码发送和校验采用失败关闭策略，不降级到进程内存或控制台明文验证码。

## 7. SMTP 配置

使用 `nodemailer` 的标准 SMTP transport，新增配置：

```env
SMTP_HOST=smtp.example.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=sender@example.com
SMTP_PASS=<个人邮箱SMTP授权码>
MAIL_FROM="Smart Finance <sender@example.com>"
EMAIL_OTP_SECRET=<独立的至少32字符随机密钥>
```

`SMTP_PASS` 表示邮箱服务商生成的 SMTP 授权码，不是用户收到的 6 位验证码。生产环境缺失或使用弱 `EMAIL_OTP_SECRET` 时启动失败并给出明确配置错误；开发和测试环境不记录明文验证码，测试通过注入假 transporter 完成。

邮件使用固定主题、纯文本正文和最小 HTML 正文，包含用途、验证码、5 分钟有效期及安全提示，不包含用户可控 HTML。

## 8. 错误处理与隐私

- SMTP 失败时不创建账号；注册发送接口返回暂时不可用。找回密码申请是防枚举规则的例外：始终返回相同受理提示，内部记录发送失败。
- 日志不得包含 SMTP 授权码、OTP、密码、完整邮箱或 Redis 原始键；邮箱日志只保留脱敏形式。
- 登录接口对“账号不存在”和“密码错误”使用相同响应。
- 验证码接口不暴露保存的摘要、剩余有效期或具体失败原因。
- 数据库异常不会签发 JWT；用户与默认账本创建失败时事务回滚。
- 游客数据迁移在账号事务提交后执行，沿用当前幂等更新行为。
- 前端不把密码和验证码写入 `localStorage`、`sessionStorage` 或 URL。

## 9. 测试策略

### 9.1 服务单元测试

- 邮箱去空格、转小写、格式校验和脱敏。
- 6 位验证码生成、HMAC 保存、用途隔离、5 分钟过期和 60 秒冷却。
- 验证错误次数、第五次失败失效和成功后的单次消费。
- 同邮箱和同 IP 发送频率限制。
- SMTP 成功、失败和邮件模板不包含敏感信息。

### 9.2 路由与数据测试

- 未验证不能注册，正确验证码可以注册并获得 JWT。
- 重复邮箱和并发重复注册由唯一约束拒绝。
- 注册失败时不留下孤立用户或默认账本。
- 邮箱登录成功、错误密码、未知邮箱、账号锁定与成功解锁。
- 找回密码申请对存在和不存在的邮箱保持相同外部响应。
- 错误、过期和重复使用的重置码不能修改密码。
- 重置成功后旧密码失效、新密码可登录。
- 新建数据库和已有数据库都能执行幂等 schema 升级。

### 9.3 前端与回归验证

- 手机号/邮箱渠道切换及三种邮箱表单状态。
- 验证码按钮倒计时、表单校验、加载状态和错误提示。
- 切换状态和刷新不会保留密码或验证码。
- 现有手机号注册、登录、找回密码及微信接口回归通过。
- 客户端生产构建通过。
- 新增目标测试全部通过；全量测试的失败数不得高于实施前已记录的基线，且不得新增与本功能相关的失败。

## 10. 验收标准

1. 现有手机号和微信认证接口契约保持不变。
2. 未验证邮箱不能创建账号，正确验证码可完成注册并登录。
3. 已验证邮箱可以使用密码登录，并可通过邮件验证码重置密码。
4. 验证码满足有效期、冷却、次数、频率和单次消费限制。
5. OTP、密码和 SMTP 授权码不出现在数据库、接口响应或生产日志中。
6. 已有数据库可无损升级，已有用户无需迁移即可继续登录。
7. 目标测试、手机号回归测试和前端构建通过，且不增加全量测试失败。

## 11. 实施边界与交付物

实现计划只应触及邮箱认证所需的 schema、配置、邮件与验证码服务、邮箱路由、登录页、API 客户端、环境变量示例和相关测试。不得顺带重构财务 Agent、RAG、报表或其他业务模块。

交付时提供个人邮箱 SMTP 配置说明，但仓库只保存变量名和占位符，不提交真实邮箱、授权码或 OTP 密钥。
